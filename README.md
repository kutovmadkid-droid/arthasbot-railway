# ARTHAS BOT — Telegram-магазин

Русскоязычный Telegram-бот: каталог подписок, корзина, профиль и реферальная статистика, редактируемая админ-панель и **ручная проверка криптооплаты** по скриншоту. Проверки блокчейна и автоматической выдачи лицензий нет.

## Быстрый запуск в Railway

1. Railway → **New Project → Deploy from GitHub repo** → выберите **этот репозиторий**. Если приватный репозиторий не виден, предоставьте Railway GitHub App доступ к нему.
2. Добавьте сервису **Volume** с mount path **`/data`**. Нельзя просто задать переменную с таким именем вместо реального Volume.
3. В **Variables** задайте:

| Переменная | Значение |
|---|---|
| `BOT_TOKEN` | Токен от официального @BotFather |
| `ADMIN_IDS` | Ваш числовой Telegram ID; несколько ID через запятую |
| `DATA_DIR` | `/data` |
| `ALLOW_MANUAL_CRYPTO_CHECKOUT` | `true` для технического включения выбранного ручного криптомодуля |

4. В настройках сервиса **Root Directory — корень репозитория**, не `/shop`. Ветка — `main`. Оставьте **одну реплику**.
5. `Dockerfile` и `railway.json` уже настроены. Start command: **`python -m shop`**. Удалите старый override `python main.py`, если он был задан вручную. Публичный домен для long polling не требуется.
6. Выполните Deploy. Каждый администратор открывает личный чат с ботом и отправляет **`/start`**, затем **`/admin`**.
7. В админке настройте поддержку, условия, категории и товары; укажите кошелёк, USDT/USDC, сеть и инструкцию. Включите товар и способ оплаты.
8. **Настройки магазина → Приём заказов** — включите после проверки настроек. Флаг окружения и этот переключатель нужны **оба**.

Токен, персональные данные и базу не добавляйте в GitHub. `.env.example` содержит только образец и не загружается автоматически. Изменять ADMIN_IDS нужно в Railway Variables, не в коде.

## Ручная обработка заказа

1. Покупатель выбирает товар, количество и сеть, переводит деньги на ваш кошелёк и нажимает **«Я оплатил»**.
2. Бот просит один скриншот обычной фотографией и отправляет его администраторам.
3. Вы **лично проверяете фактическое поступление** средств. Скриншот может быть подделан; бот не доказывает оплату.
4. **Подтвердить:** отправьте данные покупки одним сообщением (текст / фото с подписью / документ), затем подтвердите отправку покупателю.
5. **Отклонить:** напишите причину до 320 UTF-16 единиц, проверьте предпросмотр и нажмите **«Отклонить и отправить причину»**. Отказ с комментарием, фото и кнопкой поддержки придёт покупателю. Причина сохраняется в истории.
6. После обработки доступны **«Обработать следующий»** и **«Посмотреть позже»**. Незавершённые заказы остаются в очереди.

Подтверждённый заказ закрепляется за администратором; другой администратор сможет выдать его после освобождения. При неопределённом результате сетевой отправки бот требует ручной проверки доставки вместо слепого повтора.

## Что настраивается через бота

- Категории, товары, цены, описания, фото, порядок и видимость.
- Названия стандартных кнопок; названия товаров и методов оплаты.
- Фото и тексты основных экранов, название магазина и username поддержки.
- Кошельки, сети, инструкции для USDT/USDC. Цена номинально 1 USD = 1 единица стейблкоина; рыночные котировки не запрашиваются.
- Просмотр заказов, история, поиск, очередь, статистика, резервная копия.

Основная навигация редактирует карточку **фото → текст → кнопки**. Уведомления, доказательства оплаты и данные покупки идут отдельными сообщениями. Динамические системные подсказки и произвольная логика действий не являются визуальным конструктором и меняются в коде.

  __init__.py

  cover.jpg

  test_store.py

`assets` — папка, а не переименованный JPEG. Python-файлы должны находиться внутри `shop/`. Их расположение важно для сборки и импортов.

## Проверки и ограничения

Локальные проверки версии 1.1: **120 автотестов**, lint, совместимость зависимостей и 21 экран демомакета в имитации DOM. Это не гарантия идеальной работы в реальном Telegram. **GitHub Actions → Bot checks** выполняет тесты и сборку Docker на Linux после загрузки исходников; смотрите фактический результат последнего запуска, а не только локальный отчёт.

Перед продажами проверьте реальные аккаунты покупателя и администратора, фото и документы, отказ с комментарием, очередь из двух заказов, redeploy с сохранением данных и восстановление backup. Ни боевой токен, ни реальные переводы не входят в автономные тесты. Сведения о подписках и право на их продажу проверяет владелец.

**Правила Telegram:** цифровые товары и подписки, продаваемые внутри Telegram, должны оплачиваться Stars. Запрошенный криптопроцесс оставлен в проекте, однако ручная проверка скриншота не отменяет требования платформы; возможны ограничения бота. Stars в проект не добавлены. [Официальное правило](https://core.telegram.org/bots/payments-stars#faq).
