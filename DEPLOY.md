# AURORA SHOP — запуск и управление

Готовый исходный проект Telegram-бота на Python 3.13 / aiogram 3 / SQLite. Интерфейс покупателя и администратора — на русском. Блокчейн бот НЕ проверяет: решение о поступлении денег принимает человек.

## Важно перед запуском продаж

**Telegram требует Telegram Stars для цифровых товаров и подписок, продаваемых внутри Telegram. Криптовалюта не является разрешённой альтернативой для этих продаж.** Официальный источник: https://core.telegram.org/bots/payments-stars#faq

По вашему подтверждённому выбору в проекте оставлена **только ручная криптооплата**. Stars-платежи не добавлялись. Бот не обращается к блокчейну: покупатель отправляет скриншот, а администратор сам проверяет поступление и подтверждает или отклоняет заказ с комментарием. Это техническая реализация вашего сценария, а не утверждение о соответствии правилам Telegram: ручная проверка не отменяет требования платформы, возможны ограничения бота.

Для запуска выбранного модуля задайте `ALLOW_MANUAL_CRYPTO_CHECKOUT=true` в Railway Variables, перезапустите сервис, затем включите «Приём заказов» в админке. По умолчанию обе блокировки закрыты, чтобы не принимать заказы до настройки реквизитов.

## 1. Telegram

1. В официальном @BotFather создайте бота командой `/newbot`.
2. Сохраните токен. НЕ добавляйте его в репозиторий, описание проекта, скриншоты или сообщения третьим лицам.
3. Подготовьте свой числовой Telegram ID. Если знаете ID через доверенный способ, используйте его. После запуска команда `/id` в боте показывает ID отправителя; можно заменить временный положительный ID в `ADMIN_IDS` на свой и перезапустить сервис. Username не подходит для авторизации.
4. Каждый администратор обязан открыть бота и нажать `/start`. Бот не может первым начать переписку.
5. Аватар бота, его username, описание профиля и настройки BotFather не изменяются через админку магазина — это отдельные настройки Telegram.

## 2. GitHub

Распакуйте архив. Загрузите СОДЕРЖИМОЕ папки `aurora-shop` в корень нового репозитория. В корне должны лежать `Dockerfile`, `railway.json`, `requirements.txt`, а рядом папки `shop`, `assets`, `tests`. Не загружайте архив целиком вместо файлов.

Не добавляйте реальные `.env`, SQLite-базы, резервные копии, токены и данные покупателей. `.gitignore` уже настроен. Предпочтителен приватный репозиторий.

## 3. Railway

1. Создайте проект → Deploy from GitHub repo → выберите репозиторий.
2. Добавьте сервису **Volume** и задайте точку монтирования **`/data`**. База должна переживать redeploy.
3. В Variables добавьте:

| Переменная | Значение |
|---|---|
| `BOT_TOKEN` | Реальный токен BotFather |
| `ADMIN_IDS` | Ваш числовой ID; несколько через запятую |
| `DATA_DIR` | `/data` |
| `ALLOW_MANUAL_CRYPTO_CHECKOUT` | `true` для выбранной ручной криптооплаты; см. предупреждение выше |

`PORT` Railway предоставляет сам; вручную задавать его обычно не нужно. Сервис слушает `/health`. Публичный домен для long polling не требуется. Фото уже включено в архив.

4. Оставьте **ровно одну реплику**. Один токен нельзя одновременно запускать локально и на Railway. SQLite рассчитана на один сервис с одним Volume.
5. Выполните Deploy. Сначала добавьте Volume: без него в Railway приложение намеренно откажется запускаться, чтобы не потерять заказы.
6. Откройте бота → `/start` → `/admin`.

Конфигурация Docker и healthcheck включены. Volume подключается при запуске, поэтому миграция базы выполняется при запуске приложения, не в build/pre-deploy. При обновлении сервиса с Volume возможна короткая пауза. Документация Railway: https://docs.railway.com/guides/volumes

## 4. Первичная настройка в боте

- `/admin` → Настройки магазина → название и username поддержки.
- Фото и тексты → Условия покупки: напишите реальные условия, срок выдачи, возвраты, гарантию, способ активации. Ограничение текста экрана — 320 UTF-16 единиц; для полных условий можно указать публичный адрес в тексте.
- Категории → создайте категории, название/описание/фото/порядок, затем включите.
- Товары → создайте товар, укажите ID категории, название, описание, цену USD, фото, порядок. Затем включите. Есть выключенный демонстрационный товар: отредактируйте его перед продажей.
- Способы оплаты → название кнопки, монета, сеть, кошелёк, инструкция, фото. Не используйте демонстрационные реквизиты. Проверьте адрес и сеть самостоятельно.
- Фото и тексты → задайте фотографию и текст каждому экрану. Без индивидуального фото используется главное, затем встроенное космическое фото.
- Названия кнопок → редактируйте названия стандартных действий. Названия категорий, товаров и методов являются названиями соответствующих кнопок.
- `ON/OFF` скрывает сущность без удаления истории заказов. Поле «Порядок» сортирует по возрастанию.
- `/cancel` отменяет ввод; `/start` открывает главное меню; `/orders` показывает покупки; `/support` и `/paysupport` — поддержку.

## 5. Что реализовано

### Покупатель

Главная → категории → товары → описание, фото, количество `− / число / +` → купить или добавить в корзину → подтверждение условий → способы оплаты → адрес кошелька → «Я оплатил» → отправка одного фото → ручная проверка → выдача или отказ.

Профиль показывает реферальную ссылку, число приглашённых новых пользователей, число выполненных заказов, количество единиц в корзине и общее количество добавлений. Реферал закрепляется только при первой регистрации; самоприглашение и смена пригласившего блокируются. Это статистика, не денежная партнёрская программа.

Корзина: до 20 разных товаров, до 99 единиц каждого. Цена и состав фиксируются при создании заказа. Изменение цены, состава или условий перед подтверждением требует нового подтверждения. После оформления корзина очищается. До пяти неоплаченных заказов на пользователя. Все суммы хранятся в целых центах.

### Ручная обработка

1. Все администраторы получают фото чека и кнопку открытия заказа.
2. Проверьте поступление в своём кошельке: сеть, монету, сумму, адрес и финальность перевода. Скриншот может быть подделан; бот не доказывает оплату.
3. «Оплата пришла» → дополнительное подтверждение → отправьте данные покупки одним сообщением.
4. Поддерживаются текст, фотография с подписью или документ. Альбомы не поддерживаются. Затем нажмите «Отправить покупателю».
5. Бот копирует ваше сообщение покупателю и подтверждает отправку с username и ID. До отправки есть отдельное подтверждение против ошибок.
6. «Обработать следующий» открывает следующий доступный заказ. «Посмотреть позже» сохраняет его в очереди. Есть список всех заказов и поиск по номеру.
7. «Отклонить оплату» → напишите причину до 320 символов → проверьте предпросмотр → «Отклонить и отправить причину». Покупателю приходит фото, отказ, ваш комментарий, поддержка и главное меню. Причина сохраняется в заказе и видна в истории обеим сторонам. Можно изменить текст до отправки или отменить действие; до подтверждения заказ остаётся на проверке. Черновик переживает перезапуск, повторное подтверждение и изменение уже обработанного заказа блокируются.
8. Два администратора не могут одновременно подтвердить или выдать один заказ. Подтвердивший резервирует выдачу за собой; «Освободить заказ» передаёт его другому.

### Поведение при сбоях

- Данные, сессии ввода, корзины, очереди и настройки сохраняются в SQLite на Volume.
- Уведомления о чеках/отказах повторяются после временной ошибки. Повторные уведомления возможны при редком сбое между ответом Telegram и сохранением результата — это не повторная выдача.
- Telegram не даёт idempotency key для `copyMessage`. При тайм-ауте отправки данных бот НЕ пытается автоматически выдать повторно: выставляется «Нужна проверка доставки». Проверьте у покупателя, затем вручную подтвердите доставку или подготовьте выдачу заново.
- Если администратор удалит исходное сообщение до выдачи или покупатель заблокирует бота, выдача потребует ручного восстановления.
- Основные экраны редактируются в одном сообщении: фото сверху, текст ниже, inline-кнопки снизу. Чеки, данные покупки, служебные уведомления и сообщения об ошибках — отдельные сообщения. `/start` создаёт свежую карточку внизу чата. Это не обещание хранить всю переписку в единственном сообщении.
- Отказ не возвращает деньги автоматически. Возвраты выполняются владельцем вручную через поддержку.

## 6. Криптомодель и ограничения

Поддерживаются **USDT и USDC** с фиксированным выставлением 1 единица монеты за 1 USD номинальной цены. Это не рыночный обменный курс: бот не получает котировки. BTC/ETH и автоматическая конвертация не реализованы. Названия сетей и кнопок меняются свободно. Адреса, сеть и монета не проверяются блокчейном; их правильность — ответственность администратора. Комиссия должна оплачиваться сверх суммы заказа.

Бот не активирует подписки у поставщика, не продлевает их автоматически, не управляет складом лицензий и не отменяет покупки на стороне провайдера. Выдача выполняется вручную. Продавайте только лицензии/услуги, на распространение которых у вас есть право; не передавайте краденые или чужие аккаунты.

Фото загружаются через Telegram и сохраняются как file_id. При переходе на другой бот-токен загрузите фото заново: file_id привязан к боту. Все управляющие кнопки переименовываются; динамические числа, служебные подсказки/ошибки и структура действий редактируются в исходном коде, не конструктором сценариев. Произвольные новые действия нельзя создать простым переименованием кнопки.

## 7. Резервные копии и безопасность

`/admin` → Настройки → Резервная копия создаёт согласованный SQLite backup и отправляет документ администратору. База содержит Telegram ID, usernames, рефералов, заказы, настройки и идентификаторы сообщений. Она не хранит текст выданных паролей, но сообщения остаются в Telegram. Не публикуйте backup.

Включите резервное копирование Volume в Railway. Для восстановления: остановите сервис, сохраните текущую базу, восстановите `shop.sqlite3` из выбранного backup на Volume через Railway CLI, уберите только старые сопутствующие WAL/SHM файлы этой восстановленной базы при полностью остановленном сервисе, затем запустите одну реплику. Не смешивайте старые WAL и восстановленную базу. Сначала проверьте восстановление в отдельном тестовом окружении.

При смене администраторов сначала освободите их одобренные заказы. ADMIN_IDS редактируется только через защищённые переменные окружения, не через бот. Healthcheck не раскрывает заказы или секреты. Бот не запрашивает приватные ключи криптокошелька. Поддерживайте зависимости и Python в актуальном состоянии.

## 8. Локальный запуск

Python 3.13. Команды ниже выполняются из корня распакованного репозитория в собственном окружении разработчика:

```bash
python -m venv .venv
# Windows PowerShell: .venv\Scripts\Activate.ps1
# Linux/macOS: source .venv/bin/activate
python -m pip install -r requirements.txt
# Установите BOT_TOKEN и ADMIN_IDS в окружении своей оболочки.
# Для локального запуска DATA_DIR=./data; .env автоматически не загружается.
python -m shop
```

Проверки:

```bash
python -m pip install -r requirements-dev.txt
python -m unittest discover -s tests -v
python -m ruff check shop tests
```

## 9. Перед приёмом реальных заказов

Проведите тест с двумя отдельными Telegram-аккаунтами: администратор и покупатель. Проверьте фото на мобильном устройстве, каталог, корзину, профиль, реферал, доказательство оплаты, подтверждение/отказ, доставку текста/фото/документа, очередь из двух заказов, перезапуск с незавершённым заказом и восстановление backup. Отдельно оцените правила Telegram для цифровых подписок: ручная криптооплата не заменяет обязательные Stars с точки зрения платформы.

Автотесты работают без настоящего Telegram: сетевые ответы имитируются. Живой токен, реальный кошелёк и Railway-аккаунт не использовались; фактический деплой и реальные денежные переводы не проверены. Стопроцентную безошибочность в production нельзя гарантировать.

## Обновление до версии 1.1

Перед обновлением сохраните резервную копию. На старте схема SQLite v1 автоматически обновляется до v2: добавляется `rejection_reason`, существующие заказы и настройки сохраняются. Старые отказы сохранят пустую причину. После миграции старый код v1 намеренно не откроет базу v2 — для отката потребуется резервная копия прежней схемы. Ввод комментария хранится как черновик; окончательная причина и статус отказа сохраняются одной транзакцией.

## 10. Файлы

- `shop/app.py` — интерфейс, маршруты покупателя/администратора, очередь отправок.
- `shop/store.py` — транзакции, снимки заказов, доступ, состояния, backup.
- `shop/content.py` — русские тексты и названия по умолчанию.
- `shop/config.py`, `shop/__main__.py` — окружение, запуск, healthcheck, process lock.
- `tests/` — автономные тесты БД, конкуренции и пользовательских сценариев.
- `.github/workflows/ci.yml` — тесты, lint и сборка Docker в Linux при push/PR. Этот workflow настроен, но в вашем GitHub ещё не запускался.
- `verification.html`, `verification.json`, `test-results.txt` — итоговый отчёт и фактические логи локальной проверки.
- `Dockerfile`, `railway.json`, `.env.example` — развёртывание.
- `assets/cover.jpg` — встроенная фотография (Unsplash: https://images.unsplash.com/photo-1462331940025-496dfbfc7564 ; лицензия https://unsplash.com/license). Можно заменить через админку своей.
- `preview.html` — локальный демонстрационный макет, не Mini App и не платёжный сайт. Данные демонстрационные.
